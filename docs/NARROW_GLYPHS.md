# Narrow glyphs: accented Latin and Vietnamese on the device

PocketOBI's screen fonts (the classic 5x7 font and the FreeSans GFX fonts of Adafruit GFX) only hold
ASCII. Until 2.7.x every Latin-script language was therefore written without accents ("Reglages",
"Bruecke"), and Vietnamese without its diacritics. The narrow text path draws them for real.

## How a letter is drawn

`PocketTFT` (`narrow_render.h`) is the display type of every build. Its `write()` decodes UTF-8 as it is
printed, so every `print()` / `printf()` of a translated string works unchanged:

- **ASCII** goes to the normal font path, untouched.
- **An accented letter** is drawn as the *current font's own* ASCII base letter plus one to four small
  mark bitmaps (acute, grave, circumflex, caron, tilde, diaeresis, ring, dot, macron, breve, double
  acute, hook, horn, dot below, cedilla, comma below, ogonek, stroke, bar). Each mark is placed from the
  ink box of the base glyph: above it, below it, on its right shoulder (the Vietnamese horn) or across
  it (ł, đ, Đ). Two marks above stack, except that Vietnamese puts acute, grave and hook to the upper
  right of a circumflex (ấ ầ ẩ), which also saves a row. Over a large capital (18 and 24 pt) the marks
  keep their width and lose height, so a status word keeps its accent inside its card.
- **The advance is the base letter's advance.** Text stays proportional, measuring needs no new data,
  and a translated string is never wider than the same string without its accents.
- **Full glyphs** cover what is not a base letter plus marks. Today only the German sharp s (ß): the
  classic one comes from the classic font, the GFX ones are rasterised once per UI font from Noto Sans JP
  Medium (SIL OFL 1.1, already used by the CJK path), matched on the cap height. A font with no full
  glyph prints a fallback ("ss").
- **dotless i/j**: an accent on i or j replaces the dot (í, ĵ): the GFX glyph is drawn from its first
  row under the dot; the classic font has its own dotless columns.
- **With `ENABLE_CJK=1`**, any other code point goes to the wide (Japanese, Korean, Chinese) path,
  unchanged. Without it, it draws a hollow box, so a missing glyph is visible on the device.

Two marks sets exist: one drawn for the classic font and scaled with the text size, one for the GFX
fonts, scaled by the x-height (1 up to 12 pt, 2 at 18 and 24 pt).

## Coverage

Every letter of Latin-1 Supplement, Latin Extended-A and Vietnamese (Latin Extended Additional) that is
an ASCII letter plus supported marks, plus ß, đ/Đ, Ð, ł/Ł, dotless ı and the Spanish ¿ ¡. That is 268 characters: French,
German, Spanish, Polish, Czech, Hungarian, Romanian, Turkish, Vietnamese and most other Latin-script
languages. Not drawn yet: Æ æ Ø ø Œ œ Þ þ ð Ħ ħ Ŧ ŧ Ŋ ŋ Ĳ ĳ ŀ ĸ ŉ ſ and the punctuation « »
(the generated header lists them).

## The data and the generator

`glyphs_narrow.h` is generated by `tools/gen_narrow_glyphs.py` and committed, so a build never needs
the generator's inputs:

```
python tools/gen_narrow_glyphs.py            # regenerate glyphs_narrow.h
python tools/gen_narrow_glyphs.py --check    # stale header, unknown letter or string over 63 bytes -> exit 1
```

It reads the Adafruit GFX library from `.pio/libdeps` (run `pio run -e esp32-c3` once) and
`tools/.fonts/NotoSansJP-Medium.otf` (the CJK fonts folder). The letter set does not depend on the
strings: a new Latin-script translation needs no regeneration unless it uses a refused letter. The
strings are read only to refuse such a letter and a string over 63 bytes.

The path costs about 8 KB of flash in every build (measured: +7.9 to +8.6 KB per env): 266 letters x 12
bytes, two small mark sets, the sharp s in five fonts, and the drawing code.

## Measuring text

`txtW()` (classic font) and `cjkWidth()` / `gfxWidth()` (GFX font) decode UTF-8 and add each letter's
advance; `PocketTFT::getTextBounds()` replaces each accented letter by its base letter before
Adafruit's measurement. Never measure with `strlen()`: an accented letter is 2 or 3 bytes. Size every
buffer in bytes (strings are at most 63).

`upperLabel()` (the small-caps labels) also uppercases accented letters (é -> É) when the capital has
the same UTF-8 length.

## Adding a script: Cyrillic

Cyrillic (Russian) is the next table of the same kind as the sharp s: full glyphs per UI font and for the
classic font, rasterised from an OFL font that has Cyrillic, plus the shared shapes (А В Е К М Н О Р С Т
Х) that can reuse the Latin base letter. The language takes the next free pinned id (Polish has 9).

## Limits

- The classic font has no room above a capital inside its 8-pixel line: marks over a capital go one or
  two pixels above the line. Every screen is rendered and checked (`tools/screensim`) before a release.
- With an opaque text background (classic font), marks above the line are not erased by the next
  repaint of that line. A screen that repaints a classic-font capital in place over different text
  (a partial repaint) must clear the two rows above it.
